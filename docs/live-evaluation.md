# 公開デモの実モデル評価

実行日：2026-11-09（日本時間）．対象は [公開デモ](https://enterprise-ai-helpdesk.onrender.com) と架空資料のみです．参照するソースは `e433c608d0bdb351b7e3105728cda19d482e456d` です．モデル名は管理者デモの利用状況から取得しました．

## 評価計画と判定

実行前に [固定ケース8件と判定基準](live-evaluation-plan.json) を定義しました．通常質問，数値を変える誘導，社員と管理者の権限差，資料外の質問，明示的な不正指示を含みます．[実行結果](live-evaluation-results.json)には，回答本文，実際の出典，応答時間，取得できた利用履歴，ケースごとの判定を保存しています．JSON内の回答は返却された原文を保持しています．

判定は開発担当エージェントが回答本文と返却された根拠を照合しました．独立した第三者の評価ではありません．期待する回答可否，参照文書，回答要点，禁止事項を確認します．生成回答，障害時の本文抜粋，アプリ側の保留を別々に分類します．

## 制約と次回の確認

`provider_error` は通信失敗と出力検証失敗を共通の理由として返します．約25秒の応答時間からタイムアウトの可能性はありますが，プロバイダーのログを取得していないため原因は断定できません．秘密情報を含む可能性がある例外やレスポンスの全文は収集していません．

- 別日の利用可能な範囲で，LIVE-03の生成，LIVE-04の社員生成，LIVE-05の数値誘導を確認します．
- 後日の追試は別の実行記録に保存し，今回の失敗や未実行を上書きしません．
- 実モデルが根拠不足から保留する能力，悪意ある資料への耐性，言い回しを変えた攻撃，多数回の再現性は未検証です．共有資料に攻撃文を登録していません．
- HTTP応答時間にはネットワークやアプリの処理が含まれます．モデル単体の速度，休止からの起動時間，サービス全体の性能指標として一般化しません．

Issue #4は未完了として残します．今回の結果だけで網羅的な生成品質・誘導耐性・安全性を保証しません．

## 再確認の手順

1. 固定計画と既存の結果を読み，当日の利用可能枠を確認できる範囲で確認します．上限不明時も増枠・リセットせず，上限到達や障害時に止めます．
2. 役割ごとのデモへログインし，ナレッジの原文と公開設定を確認します．API利用時のCookieとCSRFトークンはメモリー内だけで保持し，成果物へ保存しません．
3. 未実行の質問を計画どおり送り，本文，出典原文，生成か抜粋か，回答時間を記録します．管理者では自身の利用履歴も確認します．
4. 本文と出典を人手で照合し，生成失敗は品質合格へ数えません．未実行と取得できなかった値を明記します．
5. 結果を別ファイルとして保存し，評価資料へのリンクを更新します．デモをログアウトして終了します．
